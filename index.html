01 // Problem Definition

What "Security Posture" Actually Means

Vulnerability scanners (Wiz) and compliance engines (Datadog) generate exhaustive lists of theoretical flaws. To an executive, raw counts do not equal risk. An unpatched CLI tool on an ephemeral CI runner is not equivalent to a remote-code-execution vulnerability on an internet-facing payment gateway.

The Executive Posture Formula
Risk = (Likelihood × Asset Impact) − Compensating Controls

True posture measures residual business exposure after network boundaries, IAM policies, and active mitigations are accounted for.

  • Likelihood: Is the asset routed to the public internet? Is the vulnerability in the CISA KEV (Known Exploited Vulnerabilities) or carrying high EPSS?
  • Asset Impact: Does the workload process Tier-1 customer PII/payments, or is it an internal staging testbed?
  • Controls: Is the host behind Cloudflare WAF, strict VPC mTLS, or read-only container rootfs?
  • Jev Verdict: Classifies into MATERIAL_RISK, CONTAINED_RESIDUAL, or NOISE_SUPPRESSED.

The 4-Stage Posture Pipeline

How Datadog CSM and Wiz feed into the TypeSafe Jev Decision Engine and output executive-ready briefings on demand.

Scanner Ingestion

Context Matrix

04 // Operationalization

Executive GitHub Actions Workflow

Executives and team leads do not need terminal access. A clean GitHub workflow_dispatch form triggers on-demand re-evaluations.

.github/workflows/generate-posture-report.yml YAML 
name: Generate Executive Security Posture Report

on:
  workflow_dispatch:
    inputs:
      environment:
        description: 'Target Cloud Environment'
        required: true
        default: 'production'
        type: choice
        options: [production, staging, all]
      risk_threshold:
        description: 'Minimum Business Impact to Alert (1-5)'
        required: true
        default: '3'
        type: choice
        options: ['1', '2', '3', '4', '5']
      notify_executives:
        description: 'Send brief to Executive Slack'
        required: false
        type: boolean
        default: true

jobs:
  triage-and-report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: pip install requests typesafe-sdk
      - name: Run Jev Triage Engine
        env:
          TYPESAFE_API_KEY: ${{ secrets.TYPESAFE_API_KEY }}
          DATADOG_API_KEY: ${{ secrets.DATADOG_API_KEY }}
          WIZ_CLIENT_ID: ${{ secrets.WIZ_CLIENT_ID }}
        run: python scripts/triage_engine.py
      - name: Publish to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./
scripts/triage_engine.py (Jev System One Core) Python 
from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

def triage_vulnerability(finding):
    with TypeSafeClient() as client:
        return client.system_one(
            state={
                "cve": finding.cve_id,
                "asset_tier": finding.asset_tier,
                "is_internet_exposed": finding.is_internet_exposed,
                "has_waf": finding.has_compensating_controls,
                "is_kev": finding.is_cisa_kev
            },
            questions=[
                Choice(
                    id="triage_verdict",
                    question="Classify executive business risk",
                    options=[
                        "MATERIAL_BUSINESS_RISK",
                        "CONTAINED_RESIDUAL_RISK",
                        "NOISE_SUPPRESSED"
                    ]
                ),
                Score(id="impact_score", min=1, max=5),
                Noul(id="is_directly_exploitable")
            ]
        )
